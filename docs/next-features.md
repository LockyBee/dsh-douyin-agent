# 后续功能候选

核对日期：2026-10-23。这是功能评估，本轮未实现或启用这些功能。先完成 1.3.2 本机更新与设置读写验收。

## 已有基础与参考

现有源码已经提供有限自主观看、行为证据与人格记忆、许可私信、自动问候、分享、评论、静默和日报。候选功能复用这些模块，优先补使用体验与可观测性。

重新核对 [c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll/tree/2d71abd25bee19a6bdc0c586b7d6e11c5ee4499c)：package.json 为 2.0.2，最近提交日期 2026-10-22，MIT，版权为 c1overzz。其 README 提供作品历史、筛选、自检与诊断等流程，适合参考页面设计；说明中也保留了不同桌面版自动运行的兼容问题。其运行链路包含 B 站 MCP、Python／本地转写等，与本项目的抖音 Playwright 和共用记忆不同，不引入它的执行依赖或账号逻辑。若后续复制代码，须固定提交并保留 MIT 原文与版权；本轮只做流程评估。

## 1. 一键自检与版本信息

在原生设置页显示实际插件版本、DSH 版本、当前通信通道与最近一次连接结果。自检依次核对设置读写准备、已有 Node、Edge、模型目录与图片输入能力、共享目录，并给出具体处理步骤。

复用 `runtime-paths.mjs`、现有 Node 探针、模型目录和设置 transport；新增脱敏诊断结果与导出按钮。默认只读，不启动浏览器、发送请求给模型或改设置。诊断不能包含 Key、Cookie、联系人、人设正文、私信和访问令牌。

优先级最高：先让使用者能判断是加载、通信、模型还是浏览器问题，减少只能截一句报错来排查的情况。

## 2. 每轮用量与费用看板

显示本轮累计输入、输出、总 token、请求次数、可用的缓存命中统计，以及每日汇总；允许设置预警线和停止后续请求的 token 预算。费用只在有明确价格来源时估算，显示价格更新时间与统计覆盖范围。

复用已有 `watch.decision` 用量事件和请求账本。仍需新增持久化累计、请求去重及前端展示；当前原生适配只保留输入、输出与总量，不能把缺失的缓存统计或费用补成零。某次请求完成后才取得实际用量，预算不能承诺账单绝不超出；模型未返回 usage 时应显示“未知”。

## 3. 看过的作品与兴趣纠偏

增加可筛选的作品列表，展示作品链接、已核实采样进度、快划／停留／分享行为和兴趣依据。提供“不计入兴趣”“少看这个题材”等反馈，明确区分大肥鱼自己的行为与用户给出的规则。

复用 `PersonaMemory` 已有作品、观看和行为证据，参考上述项目的历史列表流程。需新增分页查询与单独的反馈记录，重新计算受影响兴趣，并保留来源和版本冲突保护。不能仅凭题材识别记为喜欢，不能靠手动反馈改造历史观看事实；两种入口必须同步读取纠偏结果。

## 4. 按主题观看

在设置页添加本轮关注关键词和避开题材，可选择“看推荐”或“按主题搜索后观看”。继续使用本人允许的时段、有限轮次、模型预算和既有外发许可。

复用当前搜索工具与自主决策，在启动配置和决策上下文补充主题规则，不新增浏览器底座。规则作为任务偏好保存，不能改变人格正文、时间或联系人权限，也不能承诺仅凭作者显示名准确屏蔽某个账号。

建议先做自检和用量，再补作品列表与主题模式。这样既能解释故障和花费，也便于用户判断大肥鱼的兴趣是否学对。
