# 1.4.2 静默窗口修复

静默设置已开启但浏览器仍显示，可能是当前入口尚未重新连接已有Edge，或窗口仅有准备页、私信页，旧逻辑只查找自身的视频页。本次复用现有WatchMode、专用浏览器归属记录与CDP窗口控制，补齐已有连接与专用窗口处理；没有新增依赖。

保存静默设置时，重新连接已存在且归属核对通过的专用Edge，不启动浏览器、不新建标签、不开始轮次。作品页持续静音；仅有准备或私信页时也可最小化整个专用窗口。私信页媒体保持原设置。任一同窗页面不受本工具管理、存在登录验证或全屏状态时保留显示，并在设置页给出未最小化的原因。

手动和自主视频操作均应用静默窗口设置。准备入口首次打开会复用唯一的初始空白页，避免额外空白标签阻止归属核对。用户点击“打开抖音”仍可主动显示窗口，随后开始视频操作或重新保存静默时再次应用最小化。

软件与插件显示实际应用结果，区分开关已保存、专用浏览器已最小化、下次浏览时应用和被阻止的原因。保存状态不会伪装成窗口已隐藏。软件左栏顺序改为“对话与视频 → 业务设置 → 自主观看记录”。

窗口控制沿用[官方CDP Browser协议](https://chromedevtools.github.io/devtools-protocol/tot/Browser/)。本机验证只操作已核对的专用浏览器，不操作个人浏览器；实际回读记录最小化前后状态，不请求付费模型或执行真人发送。窗口隐藏不等于已验证长时间后台播放，本次未新增真实付费观看验收。
