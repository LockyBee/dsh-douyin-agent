# 独立软件复用记录

独立软件 1.3.2 直接连接用户填写的模型接口，使用 Electron 桌面窗口和随包 Node 后台。无需安装、启动或捆绑 DSH Host、Cordis、QQ 服务或社区 Desktop 壳。原生 DSH 插件作为同仓库的另一个入口继续维护，两边复用 32 项领域定义；模型可调用的工具仍按任务和许可过滤。

1.3.2 复用已有的静默观看、评论许可与日报 REST 接口，补软件前端，沿用固定官方 MIT 控件和渲染组件。连接错误与操作错误分别保存，恢复后只清除旧连接错误；没有新增运行依赖。桌面与界面版本在构建时交叉校验。

界面选择官方 `deepseek-ai/deepseek-harness` 固定提交 `fb2c4b9e698e30edb738bca4cf0618587db7d203` 的 MIT React 基础组件、主题和布局 CSS。它们可独立编译到前端，保留原许可证；软件自行实现任务、API 设置、时间限制、私信与分享许可的状态和交互。复用文件及来源校验见 [UPSTREAM.md](UPSTREAM.md)。

业务层沿用本项目已有的 `BrowserController`、`ChatService`、`VideoLimits`、媒体适配及记忆存储。后台使用物理 Node 的 HTTP、SQLite 和 IPC，浏览器通过 Playwright 连接系统 Edge。桌面生命周期、API Key 输入及可选系统加密、静态资源服务和 Windows 打包入口由本项目实现。

`PersonaMemory` 和 `AutonomousWatch` 使用这些领域对象，没有引入整套 DSH UI、RPC 或社区资产。1.2.0 的手动预算、自主分享与行为依据页面继续复用已引入的官方 Button、Input、Switch、Tag 和 MarkdownText 等 React 组件及 REST 会话鉴权，没有新增运行依赖。原生插件另复用已装 DSH 的 SystemPrompt 动态变量／上下文、当前模型路由与附件能力，不把这套运行服务带进独立软件。

1.1.1 继续复用现有 CDP 与媒体环境文件读取，只补打开窗口的宿主入口、音频 Key 表单和有字段白名单的本机 writer。首页及首次 Key 表单均可“打开抖音”，不需 Key、不开始计时，准备页暂停；活跃自主观看只聚焦现有页。原生命令复用 DSH commands SDK，不请求模型。Input 修复只调整本地 CSS，不改上游组件，不加外部依赖。

MiMo／MiniMax 的 Key 从“业务设置 → 音频理解”选择后端后填写，经窄 Electron IPC 写入共享媒体 `.env`。该配置在本机明文保存，不经本机 HTTP、不回显、不自动启用音频；`MediaAdapter` 读取时刷新。Whisper 无需云 Key，音频默认关闭。主模型 Key 的可选系统加密保存与这份媒体配置分别处理。

两种入口读取同一个全局位置记录，使用 `memoryDir` 与精确的 `memoryDbPath` 访问同一记忆文件夹和数据库。登记时保留旧库，不复制或迁移数据；发现路径冲突或损坏记录便停止，不静默创建另一套记忆。

人格资料独立放在共用 `memoryDir/persona/`。用户显式保存手编正文，实际观察与有依据的代理兴趣进入状态和生成区；软件通过无参 `openPersonaFolder()` 打开该目录。人格只作本机内部参考，不授予权限，代理兴趣不等于用户偏好。QQ 侧可见范围及公开分享授权尚未核实，不得因此向 QQ 群聊或公共导出扩大传播。

主要限制为抖音网页 DOM 与平台登录状态、用户设置的每日窗口及单轮时长、模型任务预算和私信许可名单。音频默认关闭，可选本地与云端后端；Python、FFmpeg、模型权重和个人凭据不随基础软件提供。

1.4.1复用VideoLimits、AutonomousWatch和Node定时器，补共享时段占位，每个允许时段最多自动一轮；默认关闭，需本人保存。请求预算为每轮1–10000、默认30，每日两入口合计20000，同轮不重置。已有轮次的停止、失败、重启不触发本时段补开。新增软件更新与图标来源及限制见[1.4.1说明](../docs/features-1.4.1.md)。

手动 API 任务预算默认 20 步、20 次工具、180 秒，用户可设 1–1000 步、1–1000 次、10–86400 秒。它独立于视频时段、单轮截止和自主观看预算，不改 DSH 外层模型的任务上限。

自主分享复用当前两位许可好友名单和官方作品卡片分享 UI。总许可默认关闭、每日默认 3 次尝试，可设 1–20 次；开启后，watch 可自己选择当前已观察作品和好友，不逐次确认，不转发私信正文、人格或私密记忆。预留扣次数，不确定或异常残留暂停并待本人核对，不自动重发，也不能靠重新开关重置收据。

兴趣由实际媒体进度与墙钟核算的时长、比例及确认的 stay／skip／分享行为形成，帧和模型信号只作观察与提案。旧记录无行为证据时为待观察，界面呈现实际时长、比例、动作和依据。

启动过程复用 Electron 与本机 HTTP：首页就绪检查、有限瞬时导航重试、去敏时间线及成功后旧错误归档均在本项目补齐。真实启动错误原因仍未确定，不宣称故障已全面消失。caret 截图修复仅在临时页面验证；当前完整验收见 [VERIFICATION.md](VERIFICATION.md)。

Node、依赖锁文件、来源与许可证在构建阶段分别核对；后台测试、界面合成测试、打包后的软件冷启动、真实模型和真人发送分开记录。新增软件不会重复原先已授权完成的真人私信或作品转发测试。当前验收范围见 [README.md](README.md)。

1.1.0 的 UI 合成与许可测试 12／12、v6 原生 SDK 临时测试 25／25 通过；该阶段根目录与 desktop 完整回归实际运行 237 项，230 项通过、0 项失败、7 项可选检查跳过，用时约 19.7 秒。1.1.0 的 `win-unpacked` 已实际打包回读，随包 Node 24.17.0、SQLite 3.53.0、27 项工具及 persona／watch 模块可导入，没有 DSH 运行包。

1.1.1 阶段 UI 完整测试 15／15 通过，包括新增输入外观 1／1、打开入口及音频 Key 合成流程 1／1。一键打开后端 6／6、相关回归 32／32，v7 原有与命令 SDK 测试合计 32／32 通过。最终完整测试数字及软件包结果另记于 [VERIFICATION.md](VERIFICATION.md)，不把合成页面当作真实抖音、云端 Key 或新 Electron 窗口验收。旧 v5 的 22 项真实工具、1.0.1 包与 1.1.0 结果分别保留，不混算为新增能力已通过。
